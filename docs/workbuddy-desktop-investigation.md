# WorkBuddy 桌面接入调查交接

2026-10-08 用户决定：当前优先完成 Codex 桌面接入；WorkBuddy 桌面调查由另一个会话独立开展。本文记录已知事实和需要回答的问题，不代表已批准创建第三方应用、申请权限、启动模型或实施 WorkBuddy 适配。

## 调查目标

确认 AgentWorkspace 能否通过可靠、受支持且获授权的接口，驱动用户本机的 WorkBuddy 桌面聊天：按持久 Agent 创建或复用独立聊天、指定实例工作根、取得真实会话 ID、持续投递消息、观察忙闲和停工，并在原入口停妥后创建唯一后继。身份、资产、检查点和执行权仍由本仓现有合同管理，不引入另一套聊天客户端或身份体系。

本地桌面聊天、CodeBuddy 受管 CLI/SDK、WorkBuddy 云端任务是三种不同接入对象，必须分别取证。给本地助理发送一条消息，或者创建一个云端任务，都不能直接证明上述完整桌面生命周期可控。

## 已知事实

- 本版仅发现 WorkBuddy 桌面安装，尚未接入完整桌面创建、投递和停工观测。以 [产品设计](design.md)、[实现登记](implementation.md) 和[当前能力说明](../src/agent_workspace/resources/prompts/capabilities.md)为准。
- 现有 E2E-002 是另一个问题：选中的 Windows 无扩展名 JS 命令行入口未进入 Node 适配，固定 SDK 连接仍报 WinError 193，认证尚未到达。不得将其误写成“桌面未登录”，也不得把修好这个 CLI 入口当作桌面集成完成。[实机失败与范围](evidence/2026-10-07-5aaae00/README.md)。
- Codex → tclaude/DeepSeek 的真实交接已经通过公开完整配置路径完成，只验证共享交接链与该 Claude SDK 路线，不证明 CodeBuddy/WorkBuddy 入口可用。[增量证据](evidence/2026-10-08-5aaae00-deepseek/README.md)。
- 2026-10-08 核对的 WorkBuddy 官方文档提供本地助理在线状态、发送消息和消息历史 API；公开接入路线涉及第三方应用注册/审核、对应 Scope 和用户 OAuth 授权。文档另有云端任务/ACP 接口，不能据此认定它能控制本机桌面会话。
- 已读到的本地助理发送消息参数主要是 content 和 msg_type，尚未据此确认独立桌面会话选择、实例 cwd、模型选择、精确忙闲或停止控制。未确认不等于上游不存在这些能力。中英文文档对 permission_response 的描述不一致，应核对目标版本和接口实际合同，不据其中一页自动代替用户审批。

官方资料：[第三方应用](https://open.workbuddy.cn/docs/third-party-app)、[Open API](https://open.workbuddy.cn/docs/openapi)、[英文 Open API](https://open.workbuddy.cn/en/docs/openapi)。调查时应重新核对页面和安装版本；不要把本文日期的资料当成永久接口合同。

## 需要回答的问题

| 问题 | 需要的证据 |
| --- | --- |
| 本机是否存在适合独立工作台使用的控制入口？ | 官方或内部接口文档、版本、调用边界；区分本机控制与云端转发 |
| 能否创建并定位独立桌面聊天？ | 返回的真实 session ID、桌面可见结果、重复请求行为；区分新建与发给当前助理 |
| 能否指定/确认实例工作根和模型？ | 实际请求参数及目标会话读回，不能只依靠提示词要求切目录 |
| 能否向指定聊天持续投递并获得完成事件？ | 同一 session 的后续轮、消息关联、忙时处理及失败/未知结果语义 |
| 能否确认旧会话停妥并安全接手？ | 原生忙闲/完成/停止证据，原会话和后继的明确边界；不强制接管 |
| 新会话如何调用 AgentWorkspace 平台工具？ | MCP 或其他受支持入口、实例身份/Binding 传递及授权边界 |
| 用户与开发者分别需要哪些配置？ | 最小应用类型、Scope、审批/授权步骤；先确认接口够用再要求用户办理 |
| 重启、断连和结果不明如何处理？ | 会话 ID 和关联是否保留，如何读回原操作；不得靠重发或重建求成功 |

## 调查方式与交付

先只读调查本机版本、官方资料及用户提供的内部资料。需要实测时，先说明具体接口、隔离数据、用户操作、模型选择和费用范围；遵守现有用户授权。不得读取或修改应用私有数据库、复制桌面凭据、冒充调用方、关闭权限校验或静默替换到 CLI/云端路线。

按每项列出“有证据可用／目标版本不支持／仍待确认”，附接口来源、最小调用结果和证明边界。优先给出最小可行接入方案及需要用户配合的事项；接口不足时明确缺哪项，而非先建设 OAuth 服务或通用协议框架。原始凭据、机器路径和私人聊天不入仓，必要的脱敏材料按 [开发规则](../AGENTS.md) 归档。

调查结果应回到本仓，更新本文结论或链接到单独报告；不要在 Codex 实现中顺手修改 WorkBuddy，两个方向分别收口。

# Workbench 0.4

本机工作台用于查看 Agent 与运行环境、消息历史、本机 AW 后台。它使用既有 HTTP 公共命令，不引入自己的聊天客户端、身份或状态机。

## 三个主页面

- **Agent 与运行环境**：按 Workspace 查看持久 Agent 身份、当前执行会话、历史 Binding 和各份本地副本。创建、模型配置、交接、Fork 与 Relay 由原生客户端、CLI 或随包 Skills 完成。
- **消息历史**：合并查看正式 AW Message 和可选原生直发记录。可以选择整个 Workspace，或某个 Agent 的收件、发件、两者。这里只读取历史，不提供聊天输入，不替 Agent 确认通知。
- **本机后台**：读取这份安装的后台状态，调用启动、停止、重启与限定日志公共接口。控制请求的返回和进程实际退出、重新就绪分别显示。

`/setup` 的配置入口和 `/sessions` 的无 Workspace 普通原生会话入口仍保留。普通会话不创建持久 Agent、Binding、正式消息或交接保证；它们不属于工作台的三个主视图。底层 Harness、Work、Delivery、共同资料与管家命令没有因页面精简删除。

## Agent 与观察依据

Agent 是持久身份，原生聊天是执行会话，目录是本地副本。同一 Agent 的多个目录不增加 Agent 数量。当前 Binding、历史 Binding、各副本的入口记录与运行器观察分别显示，不把第一个目录的旧状态接到当前执行会话上。

采用 Worker 的 Agent 在列表显示 Worker 数量和默认收件位置。进入详情后选择具体 Worker，查看它自己的当前入口、历史、本机副本和原生观察；切换 Worker 不创建会话。后台任务和日志来源也带 Worker，消息地址显示实际保存的 Worker。旧单入口 Agent 保留原显示方式。

新 Binding 的 `execution.installation_id/directory` 是入口登记来源，不证明原生会话现在仍在该机器运行。“核对本机原生会话”显式调用只读 `runtime.desktop-observe`，使用实际原生 session/host/cwd 与当前资格核对；不会创建会话或提交模型输入。页面显示核对时间，结果仅表示该次读取。其他 Harness 未接入此核对时保持未确认。

历史记录缺少来源时保留“来源未记录”，不从当前副本倒填。撤销旧 AW 执行资格也不证明旧原生聊天已经关闭。资料接续不表示完整原生聊天上下文已迁移。

`/api/state` 是只读投影，不授予执行权。同一 Workspace 的共享身份与 Binding 使用同一 Git 快照并标记 `snapshot_revision`；本地目录、runtime 和 watch 在查询时另行观察。页面显示本机查询时间与安装来源，不把查询时间当成远端心跳。

本机没有副本、单个副本状态读坏、未取得与 current 匹配的运行观察，都保持未知。可读的其他副本和共享 Binding 继续展示；缺失值不推断成运行器停止、watch 关闭或资格释放。

## 消息来源与刷新

每次进入消息历史或刷新都会重新读取 `message.list` 和 `direct-message.list`。页面按 Workspace locator 和 Agent 筛选双方记录，并显示本次读取时间。从主导航进入消息历史恢复整个 Workspace 范围，不沿用此前某个 Agent 的列表。任一来源读取失败时明确提示历史不完整，不把另一来源的空列表当作完整历史。

正式消息显示发布与通知 ACK，ACK 不代表业务完成。原生直发记录存于独立目录，不进入正式索引、ACK、投递或重试。其 `created_at` 是首次留档时间；`result/receipt` 可选，没有留档或回执不表示原生发送失败。详情只读原记录，不补发消息。

## 本机后台与日志

后台页使用 `backend.status/start/stop/restart/log`。停止请求返回 `stop_requested` 只表示收到请求。页面断开不能证明进程退出，也不代表独立原生会话关闭或 Binding 已释放。

重启请求只发一次，随后有限次只读查询状态；观察到新的进程就绪才显示重新连接成功。回复丢失时不重复控制操作，先核对当前后台。网页无法连接已停止的服务时，需要使用本次安装的启动器或原来的启动命令，再在页面重新连接。

日志只能来自本机 AW 后台或已登记 Agent 副本，不接收任意文件路径。页面保留日志来源；改变来源后需重新读取。后台状态和日志属于本机观察，不覆盖共享执行资格。

## 旧消息请求恢复

旧标签页保存的消息请求继续使用原 request ID、Binding、目标与正文。页面不会自动重发，也不生成替代 ID。

1. “查看原请求”只读查询原 operation。
2. “继续原请求”先核对已保存的原操作，再发布尚未落盘的同一请求或补原 publication receipt。
3. 已发布的请求只读确认，响应丢失后仍核对同一个 ID。
4. 移除页面提示不撤回或删除服务端记录；损坏的本页记录保持原数据并提示核对，不静默丢弃。

## 验证边界

浏览器回归使用真实本机 HTTP、无头 Chromium/Edge 与隔离 Git，覆盖三视图导航、消息刷新与范围、正式/直发来源、观察缺失/损坏、当前与旧副本、原请求响应丢失、后台控制结果和窄屏布局。明确命名的后台协议夹具只能证明显示行为，不能证明真实 OS 进程生命周期。

独立 `/setup` 与 `/sessions` 浏览器回归保留。测试不调用真实模型，不证明真实账号、生产 Git、跨机原生 Desktop 或屏幕阅读器已验收。实际后台生命周期另以隔离 home 的运行结果为据。

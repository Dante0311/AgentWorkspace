# 三个功能 Owner 的首次初始化说明

本文件只供三份 startup 提示词使用，作用与首次初始化相同。本机与云端使用同一份材料；handoff 和 relay 有各自独立的复制入口，不在 startup 中自动选择或执行。

本批同时带有用户已交付的研发任务。初始化完成后可以继续这些任务；通用初始化本身不创造业务任务。如果用户另行限定只初始化，就按该限定完成并报告。

- 实例 ID 和职责来自对应角色的 startup 文件；职责来源为协作仓 `32fb3d000bb265452e04c3918862d0025b67d1ef` 的 `definitions/<自己>/definition.md`。
- 实例长期资料保存在它自己的工作根和 `instance/<自己>`。产品仓 `Dante0311/AgentWorkspace` 是研发对象，不是实例根。

## 2. 只做首次创建与初始化

目标可以尚未创建，也可以刚由平台为本会话准备。核对实际状态，补齐本次首次启动仍缺的步骤；已经完成的步骤只读回验证，不重复执行。

有正式 AW 工具时，按 `agent` Skill 和进入材料创建/接入确实缺少的身份及首次入口。角色的 name、agent_id、definition、revision 与 [创建清单](bootstrap-manifests.json) 中的创建参数一致；平台资源由实际工具生成，不复制清单里的旧资源覆盖它。当前会话已经由平台绑定时，核对后直接初始化，不重新 start。

仅有 GitHub 工具且使用已授权 manual 路径时，按 GitHub 操作细节的首次创建与首次手动入口步骤执行。创建清单只用于这一路径，不能当作实例已经创建的证明。

两条路径都必须确认本会话实际取得当前入口资格，才写本实例资产。由平台为本会话预留的 starting 入口，按其真实进入材料完成绑定；starting 不算初始化成功。不得借用别人的 active Binding，也不能因存在同名实例就覆盖登记。

**startup 不执行接手。**已运行实例需要换会话时，报告该目标应使用独立 relay 入口；不要在本次 startup 自动消费 handoff、重新初始化原资产或重建身份。本会话本轮初始化中断后，只续做有自己实际记录支持的原操作，不另造入口。

按用户原始要求和所选职责完善自己的 AGENTS.md 与必要能力入口，复用原有七个基础 Skill，不复制产品仓 AGENTS.md 作为角色职责。不编造已安装能力，不擅自发布共享 Definition。保留已有资产及来源。

保存实际初始化资料与初始检查点，记录身份、职责来源、工具、产品分支和任务关联，明确未完成或未验证部分。AW 路径用正式 asset/checkpoint 操作；GitHub manual 路径按相同规则保存确定版本并发布检查点指针。报告真实结果后，按本轮角色文件中的已有任务继续工作；用户只让初始化时就等待后续安排。

消息、ACK、检查点和业务结果分别留证。不代收发给其他实例的通知；尤其保留原 Workbench → Lead 测试消息 `m4914c0f7229040be8bb1419fbc0c1994` 的真实状态。正常技术协作通过正式消息留痕，同时在当前会话给用户可点击的成果链接。

交付包含产品提交或 Draft PR、具体变化、实际执行的验证、明确未测项和 E2E 可执行步骤。协议、单测、真实 GitHub、Harness、Desktop、长期运行分别报告。若创建 PR，使用当前环境实际提供的附件工具关联会话。

本文件不会自动执行 handoff 或 relay；需要这些动作时分别复制相应提示词，或在有技能入口的环境调用对应 Skill。

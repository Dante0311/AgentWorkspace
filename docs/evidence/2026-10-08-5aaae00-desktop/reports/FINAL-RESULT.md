# 桌面项目与分区手动验收

日期：2026-10-08。固定产品基线：`5aaae00520374b022e0c38fa21f312f8e08629ba`。

**结论：本机项目引用、原生项目主目录和手动分区归属取得限定通过。** 本组没有执行原生 Desktop 会话、Binding 或 handoff/relay，不能计入 Desktop 自动创建或自动交接通过。

## 已验证结果

- 工作台真实 Agent 卡片能读取、保存项目名、分区名和产品目录引用；两次整页刷新后的重新打开均保留已保存内容。
- 从初始名称改为 `AW · 桌面验收 · probe` 后，以旧 revision 提交的覆盖请求返回 HTTP 409 / conflict，最终引用不变。
- 用户实际建立并编辑了一个 Codex 本地项目。原生只读接口返回的主目录精确对应本次 Agent 实例目录；用户重新打开设置后的截图显示 `desktop-probe` 标为“主要”，`product` 是另一文件夹。
- 用户将项目移入 `AW · 桌面验收` 分区。最终只读接口返回分区 ID `b45300cd-e6bf-4ffb-9753-43d2a1878d30`，其中只包含本测试项目。
- 原生项目 ID 始终为 `881c3150-ad07-43f9-b472-a550af6dc2bc`，名称与主目录不变；测试根下只发现一个原生项目。本次配置和整理复用了原项目，没有为验收创建新对话来扩大证明范围。
- 最终产品文件列表/摘要与准备时一致，共享 Git refs 与第一次引用保存后的记录一致。Agent 的 `current=null`、`has_run=false`。本组控制者没有发起模型调用，也没有创建 Binding、投递或巡检计划。

最终项目/分区以 [07 原生只读结果](evidence/07-final-native-readback.json) 为准；[08 平台终态](evidence/08-final-platform-audit.json) 核对了本机引用与实例状态。阶段性的 pending / NOT_RUN 记录仍保留，不能当作最终状态。

## 证明边界和未测项

- 平台仍返回 `manual_setup_required`、`native_project_verified=false`。这与当前实现相符：平台自己未核验或自动修改原生项目，人工验收结论另行记录。
- 附加文件夹的名称及主次关系有用户截图证据，完整附加路径没有由原生接口或截图独立读出。平台引用中的完整产品路径已核对，不能把两者混为一个证明。
- 同一原生项目 ID 的保留只证明本次改名和分区整理复用。多个真实会话的项目复用、原生规则加载、文件访问权限和模型执行未在本组验证。
- Desktop 应用版本号未单独取得；本次证据来自实际桌面界面与本机原生项目/分区接口。没有把此前 CLI 版本当作 Desktop 版本。
- 固定安装的六个相关源码/资源与基线 Git 内容经 CRLF 归一化后相同。隔离数据通过已安装产品的低层准备接口建立一个未运行实例；不将此步骤记为首次配置向导验收。
- 本组为用户操作、用户截图和控制者复核；没有第二执行者独立复核。旧批次 E2E-001 / E2E-002 残余缺陷不受本组结论影响。

## 收尾

工作台通过自有终端 Ctrl+C 停止，服务终端退出码为 1；最终进程与监听端口检查均为空，未强制杀进程。见 [09 退出审计](evidence/09-service-exit-audit.json)。

本机测试项目、测试分区和隔离数据保留；未删除或移动其他用户项目。原始截图只留本机，归档包含事实摘录与来源摘要；带控制凭据的服务日志、运行目录、无关项目/聊天清单和应用私有数据不入仓。

## 共同职责与私人修改

在新 Workspace main 发布两份小型 UTF-8 共同文件，正文分别含随机标记；创建两个角色定义，各含自身独特职责及独立 @workspace-read 指令。定义格式与操作见 [用法](shared-materials.md)。程序创建两个实例后，比对 AGENTS.md 与 definition.md 的字节摘要，确认没有机器路径替换或共同正文复制。

通过公开 workspace.read 在两实例身份下读回同一 revision 和完整随机正文，并记录工具返回，不只看生成的 AGENTS.md。启动一个真实会话，核对实际工具调用与正文返回；让模型复述本轮随机标记和自己的独特职责。需要的是“实际取得正文＋正确回应”的证据，不要求泄露推理过程。

修改共同文件，不改任何角色定义；让后继新会话正常 relay，确认它按新的进入提示读取新版本，旧会话记录仍说明旧版本。一次显式固定旧 revision 的读取仍应返回旧正文。原生会话先正常保存、停止再交接，未知结果不重建。

用第二个 AW_HOME 正常连接相同 Workspace，在不同本机目录连接未运行的实例；确认不含原路径的指引仍能读取。这个测试只证明目录与安装位置变化，跨机器可在实际第二机器具备条件时另记。对实例 AGENTS.md 加私人修改后修改上游定义，agent.versions 报本地变化，agent.update 必须拒绝覆盖。没有指令的旧定义正常创建及使用。

在一个未启动的测试角色中引用不存在文件：启动和交接预检应清楚报错，不建立额外入口、不把预检生成成功当模型已读；恢复共享文件后再按正常流程使用，不删旧回执绕过未知状态。

## 共享 Skill

发布 skills/review/SKILL.md 及配套 references/check.txt，再准备一个包含专用 skills/special/SKILL.md 的 Definition。工作台应发现 review；创建时只选择它，实例同时具有内置、专用和所选共享 Skill，未选的共享 Skill不自动出现。

已有实例补装另一个 Skill，通过目录与来源摘要核对全目录复制。更改 review 的共享版本后，仅该 Skill 显示更新；加入无关 Workspace 提交不显示变化。选择更新后实际文件一致，当前模型必须明确重读才能采用。

分别测试本地修改/添加文件、同名内置或专用 Skill、源文件删除：应拒绝覆盖或保留副本并提示，不合并私人内容。没有 Definition 的实例也能安装。记录 checkpoint 后，在另一实例目录读回共享 Skill 来源记录，不能把只在本机更新当作已经发布。

中断交换与恢复、防目录跳转、同名大小写冲突由自动回归覆盖；真实验收不需要杀掉生产进程复现。遇到自然失败时保留 pending 记录，按原 Skill 和版本恢复，不删除暂存或重新执行业务。

## Codex 项目与分区

复用新建测试实例的真实 Codex 项目，先完成一次控制连接捕获。读取桌面准备列表，核对原生 ID、实例主目录和项目名；只有名称相同、目录不同的项目不能被采用。多个同目录候选时应要求选择。

项目缺失或写接口不可用时，一次集中指引明确显示建议项目名、主目录、产品目录和分区。手动建立项目后重新发现；不把保存引用当作项目存在。首次连接尚未准备时显示 connection_required，不偷换 CLI。

有实际兼容分区工具时，明确选择已有分区或创建建议分区，核对创建返回及原生成员读回；没有符合 schema 的接口时记录“明确手动降级”，而非假通过。原生项目创建/文件夹编辑当前按公开手动边界验收。

重复同一准备请求不产生额外分区或项目、不创建聊天/Binding。用户改名或移区后重复读取，不强行搬回；之后正常启动会话应仍复用对应项目。附加产品目录实际权限和原生文件夹列表另行核对，不从平台记录推断。此组可先不调用模型。

最终提交的两版 Python、全部 Windows 分片须完成；汇总选择清单确认每个用例恰好属于一片，JUnit 与实际退出码对应，取消/失败/跳过不计通过。已有 8d86b60 分片成功只是初始检查点，不替代最终代码的结果。

在 Windows 对最终构建只运行一次 scripts/smoke_wheel.py dist，保存完整输出、真实退出码、源码提交与 wheel 摘要。它须使用经过认证的正常 HTTP 停机并等待请求处理器、自己启动的巡检线程退出，再删除自己创建的目录。关闭工作台不释放 Agent 的执行资格。

Git 普通只读对象导致的明确 PermissionError 可以只清除此文件的只读位并重试该文件一次。WinError145、其他权限错误、reparse point 或不明目录残留仍须失败并保留现场，不盲目重删、不忽略错误。失败时记录本轮目录的条目类型/属性、服务及其子进程，不扫描无关私人目录。最后确认实际进程和端口退出；强行 terminate 不算正常通过。

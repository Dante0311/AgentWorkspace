# 保存检查点

checkpoint 是可以单独使用的主动保存能力。当前入口保存以后仍可继续工作，不必等到 handoff。

## 何时主动建议

结合上次检查点之后的实际变化判断，不按固定轮数、时间或输出长度提醒。以下情况通常值得考虑：

- 一个重要阶段已完成并取得验证结果，接下来要进入另一阶段。
- 已确定关键决定、约束，或经过较长排查留下了有价值的证据、失败尝试和未决问题，重新整理会有明显成本。
- 准备切换任务、较长时间中断或更换会话，需要让之后的自己或后继知道从哪里继续。
- 宿主明确提示上下文即将压缩，或已有可靠观察表明需要保留当前工作状态；不能仅凭“聊得很久”声称已经检测到压缩。

建议时说清为什么现在值得保存、具体要保存什么。例如：“这一阶段的验证结果和方案取舍已经明确，接下来要切换任务，建议先存一个 checkpoint，方便回来继续。”同一原因已经提醒、用户未采纳且没有重要新变化时，不重复追问；刚保存过或只有零散小改动时通常不再建议。

用户已要求保存，或本任务已有按阶段主动保存的授权时，直接执行并简短告知结果，不重复请求确认。否则先建议，未得到答复时继续已授权的工作；用户说暂不保存就尊重这个选择。主动保存沿用当前授权的资料与共享范围，不自动纳入新的私人会话或外部文件，也不启动 handoff、stop 或后继会话。用户明确要求 handoff 或从当前成果 fork 时，按对应 Skill 准备所需检查点，不把阶段提醒变成重复审批。

## 保存内容与结果

使用 checkpoint.create，summary 是截至此刻的累计摘要，content 是阶段事实、决定与不确定性。
整理已有目标、关键决定、验证结果、下一步和未知结果，让之后的入口能继续。旧摘要需要结合新增事实更新，不能把“即将压缩”或“文件已保存”一句话当成完整累计摘要，也不把不确定的操作写成已经成功。
为 handoff 保存时，同时说明自己承担什么职责、正在处理什么任务、实际工作位置、已完成事项、下一步与未决结果。平台从当前登记补充 Workspace、Agent、实例分支、个人资料根、职责入口及实际会话位置；已知字段不要求模型凭记忆手填，未知位置不编造。接手时重新解析本机路径与新 Binding，不把检查点里的旧资格直接恢复。
CLI：aw -w WORKSPACE checkpoint create AGENT --binding BINDING --summary "累计摘要" --content "阶段记录"
动态工具：{"command":"checkpoint.create","arguments":{"summary":"累计摘要","content":"阶段记录"}}
工具会保存资料根中未被排除的文件快照，并按 Workspace 配置提交到本地或远端仓库；保存的不只是摘要。返回结果包含 ID、revision 与排除范围。`.git`、`.agentworkspace/local`、旧 `.aw-local`、`.local`、secrets、环境文件等按公开排除规则不上传；外部产品仓没有自动备份。发现资料根中有尚未获准共享的敏感材料时，先确认处理方式，不能假定排除规则已经覆盖它。
资产来自登记的个人资料根，不随共用项目或当前 cwd 改变。支持 worktree 的版本复用公共准备能力；若目录缺失只能取回已保存版本，须说明本轮尚未保存资料的范围，不能据此声称已经完整交接。
不要把未取得的原生记录说成已保存；如需纳入其他资料，先按使用者选择保存或提供固定引用。snapshot 后无权修改旧检查点，纠正应新增。
检查点不释放控制权。停工交出由 handoff/stop 完成，Fork 只选已经保存并登记的检查点。

确认实际保存结果后，简短说明保存了什么及检查点 ID；失败或结果未知时如实说明，按原检查点 ID 核对，不另建重复保存。本指引是 Agent 主动判断与调用能力，不表示已经安装压缩钩子、定时保存或完整原始记录归档。

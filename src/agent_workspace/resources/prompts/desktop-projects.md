# 桌面项目与分区：持久 Agent 的手动准备

一个 Agent 在实际使用的桌面端复用一个项目，不为每次会话新建项目。项目名默认 `AW · Workspace · Agent`；Codex 分区默认 `AW · Workspace`。只有首次实际使用时才准备；不批量建立三家项目，不复制产品仓，不写入应用私有数据库。

1. 在所选原生桌面端，选择已有项目或手动新建。使用返回的项目名称和 `primary_folder`，把 **Agent 已有实例目录** 设为主目录，不是选择产品目录代替。
2. 按需关联 `product_paths` 中的产品目录。Codex 支持多文件夹的版本可在项目菜单编辑文件夹并指定主文件夹；其他桌面端只使用实际提供的功能，附加目录与规则加载未验证时先说明限制，不假装已授予访问权。
3. Codex 可使用返回的分区名手动建立/选择分区，把对应 Agent 项目放入其中。使用用户已有布局时，在本机保存其实际显示名。后续不会强行重命名、移动或重新归类。其他桌面端不假设存在相同分区接口。
4. 项目设置中不再复制完整角色指令，职责以实例内 AGENTS.md、Skill 与资料为准。访问产品前按需要读取产品规范；主目录与附加目录分开不等于强制隔离，也不关闭项目/用户配置的原生继承。
5. 原端完成 handoff 并确认交出后，在同一个 Agent 项目中新建会话，再按 relay 指引接手。已捕获真实控制连接的 Codex Desktop 由运行器完成新聊天创建与绑定；手动入口按提示操作。不复用已交出的旧会话，不产生第二个有效执行者。只打开项目或新建窗口不等于 Binding 已建立。

此偏好页面保存本机名称与目录引用，**保存本身不创建或修改原生项目/分区**；Codex Desktop 启动时另行读取真实项目列表、核对实例主目录并复用匹配项目。`manual_setup_required` 不是临时故障，不要循环重试。项目整理失败不妨碍已支持的 CLI 使用，但不得暗中把 Desktop 请求改成 CLI。原生桌面支持范围以当前 capabilities.md 为准。

普通会话直接选择已有产品目录；不建立专属 Agent 项目、管家或 Workspace。会话要求作为原生输入，不写入共享 AGENTS.md。普通会话不获得平台 Message/ACK、持久身份和自动交接保证。CLI 不需要桌面项目或分区。

完成一次真实控制连接捕获后，可用 agent.desktop-discover 统一发现，再由用户用 agent.desktop-prepare 选择匹配项目，可靠 ID 与主目录一起保存。同名而目录不符不能采用，多候选请明确选择。原生项目创建/文件夹编辑无已核实写合同时仍按上面的集中指引手动完成。

分区可跳过；只有实际工具 schema 符合本版窄适配时才执行明确选择的创建/移动，并读回核对成员关系。缺接口或分区查询失败不阻塞项目复用，不修改私有数据库。相同 request ID 返回原结果，不把用户后来改名/移动强行复原；结果未知保留回执，不换 ID 盲目重发。准备不创建模型会话或 Binding，也不证明附加目录已经获得原生权限。

| 文件 | 职责 |

## 这版落实的使用路径

无 Definition/Work 创建 → 独立资料根 → 预留唯一新入口 → 按实际 Adapter 绑定原生会话 → 自动收发/主动收件 → 检查点 → 明确 stop → 新会话接手。可从检查点另建实例，不过滤已有资产、不复制原执行资格。

没有具体任务时，初始化提示词要求简短问候与初始检查点，不自行查询产品或试做任务。CLI 运行器额外根据实际首次轮次结束事件保存初始快照，不将失败轮次报告为初始化完成。

轮询、模型输入与消息发送不等待整个模型轮次串行完成。Git CAS 负责共享竞争；本机 OS 锁加共享 binding controller 防止另一个目录/进程并行驱动同一实例。桥接异常可有限重启，主动关闭与 handoff 不自动拉起。

## 尚待实机验收 / 明确没有实现

**Desktop：** 已实现控制客户端、工具能力核对、真实 session 绑定、新会话 composer 入口、有限重连。未在真实用户版本跑通，也没有自动发现所有版本安装路径/新管道；首次仍可能需要 capture 和手动发送入口提示词。

**Codex：** 已实现 app-server 协议和动态工具，对应协议 peer 测试不等于真实模型运行。没有验证账号登录、Windows `.cmd`、当前原生权限及长期运行。

**企业微信：** 已实现可选官方 SDK 文本通道代码、通用桥接协议与监督；真实 Bot 鉴权/群聊未验证。多模态、文件、卡片不是本次插件实现范围。

**远端：** 本地 Git 远端是真实测试；GitHub REST 是协议测试，没有用生产 token 跑平台的双仓收发。限流、企业策略、生产规模仍需实测。

**恢复：** 原操作补齐、明确关闭和局部重连已做；完全丢失的原生会话、不明 thread 创建、硬崩溃占位都保留事实并停止，不提供强制接管或任意自动重放。日志与本机 journal 不默认承诺全部跨机恢复。

**范围：** 没有 V2 多 Workspace 独立身份、V3 统一聊天与多事务会话、Merge、智能记忆筛选、复杂权限或插件市场。选定普通文件导入不是 SBP/NRCHome 全量迁移器。

原先的真实 Desktop 进入、收发、handoff、同 App 换会话实测仍须完成，但单条路径已不足以代表新确认的 V1 范围。不得以本地测试或 CLI 成功代替 Desktop 验收；新增闭环见下节。

## 新确认的 V1：实现差距与接续顺序

完整产品合同仅在 [design.md](design.md) 维护，这里记录差距，不另建平行设计。以下工作均为待实现或待扩展，不因本次落档标为完成。

| 工作 | 当前差距与下一步 |
| --- | --- |
| 通用 Harness/模型配置 | 目前仍是固定 Runtime 配置，缺少通用发现、认证/能力展示及按服务选择模型与推理强度的流程。先核对目标入口的原生接口/SDK，使用实例级配置，不改用户全局设置。 |
| 自动会话与通信 | 已有 Codex/Desktop 适配基础，但不等于全部目标通过。Codex、Claude Code、WorkBuddy 的 Desktop/CLI 按实际产品入口分别记录版本、创建/连接、状态/事件、输入和停工确认；不将缺失能力默默换成 CLI。 |
| 同实例跨 Harness 交接 | 复用检查点、Binding 和 handoff/relay，补齐目标预检、按所选配置创建新会话与自动接手；至少实测 Codex 到 Claude Code CLI，验证后续消息进入新会话。手动路径单独保留。 |
| 管家小组创建 | 当前未内置三份管家 Definition，也未在 Workspace 初始化时创建三名实例。通过普通创建流程装配，补齐幂等创建、无 Provider 待配置、已有空间显式补建与最小管理授权。 |
| 巡检与维修 | 已有局部连接/桥接看护，不是 Workspace 管家。补结构化检查、Sentinel 管理的持久计划、独立程序触发、Maintainer 的受限修复与复查；异常和自身失联可见，不重放未知业务。 |
| 企业微信与扩展 | 现有文本桥接需真实验收；企业微信是 V1 渠道目标，启用仍可选。Harness 与 Channel 开放最小扩展合同，复用上游能力，不建设插件市场。 |

按“验证实际接入与配置 → 跑通创建/通信/交接 → 复用同一路径建立管家小组 → 接通巡检维护和渠道”的顺序逐步提交；不是为管家另写一套运行引擎。底层身份创建仍不偷偷调用模型，用户明确选择的创建并启动流程则必须自动完成。

用户反馈此前 Codex CLI 指定 URL/API 凭据的路径可行，可作为验证起点；这是用户提供的经验，不是本仓对目标版本、服务或所有模型的验收结论，不在文档中保存真实凭据。ACP、CC Switch、AgentAPI、LiteLLM 等尚未选定为依赖；具体复用对象按实际收益、维护、许可与兼容性重新评估。

实现同时更新对应 Skill、使用说明和界面。当前 Skill/usage 继续说明可执行的预览命令，不先发布不存在的管家或发现命令。以 design.md 第 13 节逐项留证；不重写原验证记录，不声称新的会话能力、权限边界或外部系统已被本次文档检查验证。
